# Revision Report: Heterogeneous InherNet Performance Diagnosis & Fixes

> **Date**: 2026-03-11 08:43  
> **Scope**: `ResNet18HeteroSVD`, `DecoupledGatedSVDConv2d`, `train_hetero_svd_model`, and main experiment block  
> **Observation**: Hetero-InherNet performs close to but consistently below the original Uniform NNI (InherNet) across all head/init configurations.

---

## Executive Summary

Seven issues were identified — three critical, two high-impact, and two medium-impact. They interact and compound each other. The single most damaging issue is that **the hetero model performs SVD on random (untrained) weights, completely violating the "inheritance" paradigm**. Fixing this alone would likely close most of the gap. The remaining issues refine rank allocation quality, expert diversity, and gradient flow.

---

## Issue 1 — [CRITICAL] SVD Applied to Random Weights Instead of Trained Weights

### Diagnosis

This is the **root cause** of the performance gap.

In the main block, the old method works on a **trained** model:

```python
model = ResNet18SVD(num_classes=num_classes).to(device)
# ... model is trained for epochs_num epochs ...
train_svd_model(model, rank, head_num, ...)  # deepcopy of TRAINED model → SVD → retrain
```

But the hetero model is **never pre-trained**:

```python
hetero_model = ResNet18HeteroSVD(num_classes=num_classes).to(device)
# hetero_model is NEVER trained — weights are random!
train_hetero_svd_model(hetero_model, ...)  # deepcopy of RANDOM model → SVD → train from scratch
```

### Why This Matters

The entire InherNet paradigm is **inheritance**: the student inherits the teacher's learned representations via SVD. When applied to trained weights:

- Singular values decay rapidly → clear low-rank structure exists
- Dominant SVD bases ($U_r$, $V_r$) capture the semantically meaningful directions
- The rank-$r$ approximation preserves most of the signal energy
- Spectral entropy varies meaningfully across layers → entropy-based allocation is informative

When applied to random weights (Kaiming init or similar):

- Singular values follow the Marchenko–Pastur distribution → nearly uniform, no low-rank structure
- SVD bases are random orthogonal directions → no semantic content to "inherit"
- The spectral entropy is near-maximum for all layers → entropy-based allocation degenerates to near-uniform allocation — **defeating the entire purpose of heterogeneous rank assignment**
- The covariance $\Sigma_x$ estimated from random-weight forward passes captures almost none of the true data distribution structure

The hetero method is therefore not inheriting anything — it is training a randomly-factorized architecture from scratch. That it still reaches ~83% is purely because the factored architecture (conv1 + gated expert conv2s) can still learn, NOT because of any meaningful initialization transfer.

### Fix

**Option A (Recommended):** Pre-train `hetero_model` before decomposition, mirroring the old method:

```python
# Train hetero_model's base ResNet-18 first
print("Training Hetero base ResNet-18...")
optimizer_hetero = optim.Adam(hetero_model.parameters(), lr=0.001)
train_model(hetero_model, train_loader, test_loader, criterion, optimizer_hetero, epochs=epochs_num)

# Now the hetero SVD will decompose TRAINED weights
for cfg in hetero_configs:
    train_hetero_svd_model(hetero_model, ...)  # deepcopy of TRAINED model
```

**Option B (Lighter):** Copy the trained model's weights into `hetero_model`:

```python
# After training model (ResNet18SVD), transfer weights
hetero_model.resnet.load_state_dict(model.resnet.state_dict())
```

Option B is cleaner because it re-uses the same trained teacher, making the comparison between old and new decomposition methods purely about decomposition quality rather than teacher differences.

### Expected Impact

**+1–3% accuracy**, plus faster convergence (meaningful initialization vs. random).

## Issue 2 — [CRITICAL] `min_rank=1` Allows Destructive Bottlenecks

### Diagnosis

In `_allocate_ranks_by_entropy`, the parameter `min_rank=1` (hardcoded in the call from `apply_hetero_svd`):

```python
rank_map = self._allocate_ranks_by_entropy(entropies, max_ranks, budget_ratio=budget_ratio, min_rank=1)
```

This allows any layer to be compressed down to rank **1** — a single rank-1 factorization. Even with `budget_ratio=0.35`, the entropy-proportional allocation can assign extremely low ranks to "low-entropy" layers.

For a ResNet-18 with 20 conv layers, the approximate max-rank profile is:

| Layer group | Max rank per layer | Count |
|---|---|---|
| conv1, layer1.*, downsample 1x1s | 64 | ~6 |
| layer2.* | 128 | ~4 |
| layer3.* | 256 | ~4 |
| layer4.* | 512 | ~4 |
| downsample 1x1 (layer3, layer4) | 128, 256 | ~2 |

Total max ranks ≈ 4352. Budget at 0.35 = ~1523 total ranks across 20 layers. Average rank ≈ 76.

**But** the first few layers (max_rank=64) and later layers (max_rank=512) have vastly different scales. With purely entropy-proportional allocation, early layers with low entropy can get rank 1–3. These become **information bottlenecks** — all subsequent layers are limited by the most compressed representation in the pipeline.

### Fix

1. **Raise `min_rank` in `_allocate_ranks_by_entropy`** to a meaningful floor (e.g., 8 or 16):

```python
rank_map = self._allocate_ranks_by_entropy(
    entropies, max_ranks,
    budget_ratio=budget_ratio,
    min_rank=max(8, int(0.1 * min(max_ranks.values())))  # at least 10% of smallest layer
)
```

2. **Add a `min_rank` parameter to `apply_hetero_svd`** and pass it through instead of hardcoding:

```python
def apply_hetero_svd(self, calib_loader, head_num=2, budget_ratio=0.35, r_min=4, min_rank=8, max_calib_batches=5):
    ...
    rank_map = self._allocate_ranks_by_entropy(entropies, max_ranks, budget_ratio=budget_ratio, min_rank=min_rank)
```

### Expected Impact

Prevents catastrophic information loss at narrow layers. **+0.5–1% accuracy**.

## Issue 3 — [CRITICAL] Spectral Entropy Uses $\sigma_i$ Instead of $\sigma_i^2$

### Diagnosis

The code computes:

```python
sigma_sum = s.sum().clamp_min(1e-12)
p = (s / sigma_sum).clamp_min(1e-12)
entropy = -(p * torch.log(p)).sum().item()
```

This uses the raw singular values $\sigma_i$. But the **von Neumann spectral entropy** from quantum information theory is defined over the **eigenvalues** of the density matrix $\rho = W^\top W / \operatorname{tr}(W^\top W)$, whose eigenvalues are $\sigma_i^2 / \sum_j \sigma_j^2$.

Using $\sigma_i$ instead of $\sigma_i^2$:

- **Underestimates** the entropy contrast between layers (since $\sigma_i$ decays slower than $\sigma_i^2$)
- Leads to **more uniform** rank allocation than intended
- Layers with truly concentrated spectra (should get low rank) are over-allocated
- Layers with truly spread spectra (should get high rank) are under-allocated

### Fix

```python
s_sq = s ** 2
sigma_sum = s_sq.sum().clamp_min(1e-12)
p = (s_sq / sigma_sum).clamp_min(1e-12)
entropy = -(p * torch.log(p)).sum().item()
```

### Expected Impact

Sharper, more meaningful rank differentiation across layers. **+0.3–0.8% accuracy** (especially combined with Issue 1 fix, since trained weights have much clearer spectral structure).

## Issue 4 — [HIGH] Expert Symmetry Not Broken

### Diagnosis

In `_replace_conv_with_hetero_svd`, all $H$ expert up-projections are initialized **identically**:

```python
for _ in range(head_num):
    conv2 = nn.Conv2d(rank, c_out, kernel_size=1, ...)
    conv2.weight.data = (u_trunc @ torch.diag(s_trunc) / head_num).view(c_out, rank, 1, 1)
    # ALL experts get the SAME weight
```

Consequences:
1. All experts produce identical outputs at initialization
2. The gate receives no gradient signal for differentiation (∂L/∂gate ∝ expert_i − expert_j = 0)
3. Experts remain correlated throughout training, reducing effective capacity

The old method has the same issue but compensates through: (a) higher uniform rank providing more capacity for eventual divergence, (b) the gate's random initialization eventually creates small asymmetries that accumulate.

With the hetero method's smaller ranks at some layers, there is less "room" for experts to diverge organically.

### Fix

Add controlled perturbation to break symmetry, following the **asymmetric initialization** described in summary.md:

```python
s_sqrt = torch.sqrt(s_trunc)

for h in range(head_num):
    conv2 = nn.Conv2d(rank, c_out, kernel_size=1, ...)
    base_weight = (u_trunc @ torch.diag(s_sqrt) / head_num).view(c_out, rank, 1, 1)
    # Add scaled noise for diversity
    noise_scale = 0.01 * base_weight.std()
    noise = torch.randn_like(base_weight) * noise_scale
    conv2.weight.data = base_weight + noise
    conv2_list.append(conv2)

# Also update conv1 with sqrt(Σ) on the other side:
conv1.weight.data = (torch.diag(s_sqrt) @ v_h_trunc).view(rank, c_in, k_h, k_w)  # after un-whitening
```

This serves dual purposes: (a) $\Sigma^{1/2}$ split balances gradient magnitudes between conv1 and conv2, (b) noise breaks symmetry for expert specialization.

### Expected Impact

Faster expert specialization, better final accuracy in multi-head configurations. **+0.3–0.7% accuracy** for $H \geq 2$.

## Issue 5 — [HIGH] Redundant Cholesky/SVD Computation

### Diagnosis

The Cholesky decomposition and full SVD are computed **twice** for every layer:

1. In `_compute_spectral_entropies`: computes `chol_c`, whitens, does SVD → used only for entropy
2. In `_replace_conv_with_hetero_svd`: computes `chol_c` AGAIN, whitens AGAIN, does SVD AGAIN → used for actual decomposition

The SVD of large weight matrices is $O(mn \min(m,n))$ — this is the most expensive operation in the pipeline and is being doubled.

### Fix

Cache and reuse the SVD results from `_compute_spectral_entropies`. The `svd_cache` is already partially built but never used:

```python
def _compute_spectral_entropies(self, covariances):
    ...
    svd_cache[name] = {
        's': s,
        'v_h': v_h,
    }
    return entropies, max_ranks, svd_cache  # svd_cache is returned but NEVER used
```

In `apply_hetero_svd`, the cache is discarded:

```python
entropies, max_ranks, _ = self._compute_spectral_entropies(covariances)  # _ = discarded!
```

**Fix**: Store full SVD results (including $U$) in the cache, pass to replacement function:

```python
# In _compute_spectral_entropies, also store u and chol_c:
svd_cache[name] = {'u': u, 's': s, 'v_h': v_h, 'chol_c': chol_c}

# In apply_hetero_svd:
entropies, max_ranks, svd_cache = self._compute_spectral_entropies(covariances)
# Pass cache to _replace_conv_with_hetero_svd
replaced = self._replace_conv_with_hetero_svd(module, rank=..., head_num=..., cov=..., r_min=..., svd_cache=svd_cache[name])
```

### Expected Impact

~2× speedup in the decomposition phase. No accuracy change, but critical for scaling to larger models.

## Issue 6 — [MEDIUM] Rank Allocation Lacks Temperature Smoothing

### Diagnosis

The current allocation is purely linear-proportional:

$$r_l = \frac{\mathcal{H}_l}{\sum_j \mathcal{H}_j} \cdot \mathcal{B}$$

This can produce extreme allocations where some layers get very low ranks while others get very high ranks. Even with the min_rank fix from Issue 2, a smoother allocation would be more robust.

### Fix

Add a temperature parameter $\tau$ and a guaranteed floor $r_{\text{floor}}$:

$$r_l = r_{\text{floor}} + \frac{\mathcal{H}_l^{1/\tau}}{\sum_j \mathcal{H}_j^{1/\tau}} \cdot \left(\mathcal{B} - N \cdot r_{\text{floor}}\right)$$

Where:
- $\tau = 1.0$: current behavior (linear)
- $\tau > 1.0$: more uniform (safer, more conservative)
- $\tau < 1.0$: more extreme (sharper differentiation)

A recommended default is $\tau = 1.5$ with $r_{\text{floor}} = 8$.

```python
def _allocate_ranks_by_entropy(self, entropies, max_ranks, budget_ratio=0.35, min_rank=8, temperature=1.5):
    layer_names = list(entropies.keys())
    total_max = sum(max_ranks[name] for name in layer_names)
    budget = int(max(len(layer_names) * min_rank, round(total_max * budget_ratio)))
    budget = min(budget, total_max)

    n_layers = len(layer_names)
    floor_budget = n_layers * min_rank
    remaining = max(0, budget - floor_budget)

    # Temperature-smoothed entropy
    smoothed = {name: entropies[name] ** (1.0 / temperature) for name in layer_names}
    smoothed_sum = sum(smoothed.values())
    if smoothed_sum <= 0:
        raw = {name: remaining / n_layers for name in layer_names}
    else:
        raw = {name: (smoothed[name] / smoothed_sum) * remaining for name in layer_names}

    ranks = {}
    for name in layer_names:
        ranks[name] = min_rank + int(round(raw[name]))
        ranks[name] = min(max_ranks[name], ranks[name])
    ...
```

### Expected Impact

More robust rank distribution, avoids extreme outlier allocations. **+0.2–0.5% accuracy**.

## Issue 7 — [MEDIUM] No Load-Balancing Auxiliary Loss for Gating

### Diagnosis

Standard MoE practice (Switch Transformer, GShard, etc.) includes an auxiliary loss to prevent routing collapse:

$$\mathcal{L}_{\text{balance}} = \alpha \cdot N \sum_{h=1}^{H} f_h \cdot P_h$$

Where $f_h$ = fraction of tokens routed to expert $h$, $P_h$ = mean gating probability for expert $h$.

Without this, one expert can dominate (receiving almost all routing weight), leaving other experts underutilized. Combined with the symmetry issue (Issue 4), this is especially problematic.

### Fix

Add a `load_balance_loss()` method to `DecoupledGatedSVDConv2d` that accumulates during forward:

```python
class DecoupledGatedSVDConv2d(nn.Module):
    def __init__(self, ...):
        ...
        self._last_gating_weights = None  # for aux loss

    def forward(self, x):
        ...
        gating_probs = F.softmax(gating_scores, dim=-1)  # (B, H)
        self._last_gating_weights = gating_probs
        ...

    def load_balance_loss(self):
        if self._last_gating_weights is None:
            return 0.0
        g = self._last_gating_weights  # (B, H)
        f = g.mean(dim=0)              # mean prob per expert
        return (f * f).sum() * self.head_num  # encourages uniformity
```

Then in the training loop, collect and add the auxiliary loss:

```python
aux_loss = sum(
    m.load_balance_loss() for m in model.modules()
    if isinstance(m, DecoupledGatedSVDConv2d)
)
loss = task_loss + 0.01 * aux_loss
```

### Expected Impact

Better expert utilization, prevents routing collapse. **+0.2–0.5% accuracy** for $H \geq 2$.

## Appendix A: Detailed Weight Flow Comparison

### Old Method (Uniform NNI)

```
Trained W ──SVD──▶ W ≈ U_r Σ_r V_r^T
                    │
              ┌─────┴─────┐
              ▼           ▼
         conv1: V_r^T   conv2_h: U_r Σ_r / H  (×H heads, all identical)
              │           │
              └─────┬─────┘
                    ▼
             GatedSumConv2d (gate operates on compressed features)
```

### New Method (Hetero, Current — Broken)

```
RANDOM W ──Whiten──▶ W̃ = WC ──SVD──▶ W̃ ≈ U_r Σ_r V_r^T
                                        │
                                  ┌─────┴─────┐
                                  ▼           ▼
                        conv1: V_r^T C^{-1}   conv2_h: U_r Σ_r / H
                                  │           │
                                  └─────┬─────┘
                                        ▼
                                 DecoupledGatedSVDConv2d
```

### New Method (Hetero, Fixed)

```
TRAINED W ──Calibrate──▶ Σ_x = CC^T
           ──Whiten──▶  W̃ = WC ──SVD──▶ W̃ ≈ U_r Σ_r V_r^T
                                           │
                     rank r_l allocated by entropy of σ²(W̃_l)
                                           │
                                     ┌─────┴─────┐
                                     ▼           ▼
                        conv1: Σ^{1/2} V^T C^{-1}  conv2_h: U Σ^{1/2}/H + ε_h
                                     │           │
                                     └─────┬─────┘
                                           ▼
                                    DecoupledGatedSVDConv2d
                                    + load_balance_loss()
```
